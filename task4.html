Objective of the Firebase IoT monitoring system

Build a secure, real-time web dashboard that shows live temperature, humidity and light readings from the ESP32, lets a signed-in user control the bulb, and stores every reading in the cloud. Task 5 builds on this with logging, automation and data export.

Learning objectives

  • Design a NoSQL schema optimised for real-time queries
  • Implement Firebase Authentication with email/password and Google sign-in
  • Write security rules that protect data while allowing the needed access
  • Keep several clients (ESP32 and dashboards) in sync in real time
  • Optimise queries and understand the cost and limits of the free tier
  • Build a responsive web dashboard that updates without a page refresh and exports data as CSV

Basic concept of Cloud Computing

Cloud computing means using computing resources (servers, storage, databases, software) over the internet, paid for or used as needed, instead of owning and running the hardware yourself. The provider handles maintenance, scaling and uptime.

IaaS, PaaS, SaaS and BaaS

ModelWhat you getExample
IaaS (Infrastructure as a Service)Raw virtual machines, storage and networks. You manage the OS and everything aboveAWS EC2, Google Compute Engine
PaaS (Platform as a Service)A ready platform to run your code. You manage the app, not the serversGoogle App Engine, Heroku
SaaS (Software as a Service)Finished software used through a browserGmail, Google Docs
BaaS (Backend as a Service)Ready-made backend features (database, authentication, hosting, functions) used through an SDKFirebase (used in this project)

What a Cloud Platform is

A cloud platform is a provider’s collection of online services that can be combined to build applications. Firebase is a platform by Google offering a database, authentication, hosting and cloud functions. Adafruit IO (Task 2) is a smaller, IoT-specific platform.

What a Database is, and the Firebase Realtime Database

A database is an organised store of data that can be written, queried and kept safely. The Firebase Realtime Database (RTDB) is a cloud-hosted NoSQL database that stores data as one large JSON tree. Its key feature is real-time sync: clients keep a connection open, and when a value changes, every connected client (the ESP32 and every open dashboard) is notified within about a second, with no refreshing.

What a Cloud-Based Dashboard is

A cloud-based dashboard is a web page that reads data from a cloud service and displays and controls it from any device with a browser. Here the dashboard listens to RTDB paths, so the cards, toggle and table update on their own when the ESP32 writes new data.

Authentication, and the purpose of a login system

Authentication answers “who are you?”. Firebase Authentication verifies identity with an email and password or a Google account and issues a secure token. The login system matters because the dashboard can switch a 230 V appliance and shows private data. Without it, anyone who found the URL could use it.

Difference between Authentication and Authorization

AuthenticationAuthorization
QuestionWho are you?What are you allowed to do?
WhenAt sign-inOn every read or write

Firebase project setup

  1. Open the Firebase console and create a project (Analytics optional).
  2. Add a Web app (</>) and copy the firebaseConfig object into the dashboard.
  3. Create a Realtime Database and start in locked mode. Then publish the rules from code/database.rules.json.
  4. Note the database URL, which is also needed by the ESP32 firmware.

Firebase Authentication configuration

  1. Authentication → Sign-in method: enable Email/Password and Google.
  2. Authentication → Settings → Authorized domains: add the domain the dashboard is hosted on (for example localhost and the GitHub Pages or Firebase Hosting domain).
  3. Create one dedicated user for the ESP32 (for example device@…). The firmware signs in as this user.
  4. If it is a personal project, disable open sign-ups afterwards, since any signed-in user can control the bulb under these rules.

Realtime Database structure

The structure is deliberately flat. Deeply nested paths force larger downloads and make queries slow.

/
├── sensorData/
│   └── <pushId>/             one record per reading (2 s apart)
│        ├── temperature  22.5
│        ├── humidity     59
│        ├── ldr          1200
│        ├── bulbState    false
│        ├── mode         "manual"
│        └── timestamp    1726123800000   (server time, ms)
├── appliances/
│   └── bulbState         true | false    (manual command + current state)
├── settings/
│   ├── mode              "manual" | "automatic"
│   └── ldrThreshold      0 … 4095
└── users/<uid>/          email, createdAt, lastLogin
Show security rules (database.rules.json)
{
  "rules": {
    "sensorData": {
      ".read": "auth != null",
      ".write": "auth != null"
    },
    "appliances": {
      ".read": "auth != null",
      ".write": "auth != null"
    },
    "settings": {
      ".read": "auth != null",
      ".write": "auth != null"
    },
    "users": {
      "$uid": {
        ".read": "$uid === auth.uid",
        ".write": "$uid === auth.uid"
      }
    }
  }
}

<script>
  // databaseURL, authDomain and projectId follow from the project name; paste your apiKey (and appId)
  // from Firebase console > Project settings > Your apps
  const firebaseConfig = {
    apiKey: "YOUR_API_KEY",
    authDomain: "manasa-easports.firebaseapp.com",
    databaseURL: "https://manasa-easports-default-rtdb.asia-southeast1.firebasedatabase.app",
    projectId: "manasa-easports"
  };
  firebase.initializeApp(firebaseConfig);
  const auth = firebase.auth(), db = firebase.database();
  const $ = id => document.getElementById(id);

  let mode = "manual", bulbOn = false, history = [], started = false;

  /* ---------- Authentication ---------- */
  const showErr = e => $("err").textContent = e.message;
  $("btnLogin").onclick  = () => auth.signInWithEmailAndPassword($("email").value, $("password").value).catch(showErr);
  $("btnSignup").onclick = () => auth.createUserWithEmailAndPassword($("email").value, $("password").value).catch(showErr);
  $("btnGoogle").onclick = () => auth.signInWithPopup(new firebase.auth.GoogleAuthProvider()).catch(showErr);
  $("btnLogout").onclick = () => auth.signOut();

  // Session persists across reloads; this decides which view to show
  auth.onAuthStateChanged(user => {
    $("loginView").hidden = !!user;
    $("dashView").hidden = !user;
    if (user && !started) { started = true; startListeners(); }
  });

  /* ---------- Real-time listeners ---------- */
  function startListeners() {
    db.ref("sensorData").limitToLast(50).on("child_added", snap => {
      const d = snap.val();
      history.push(d); if (history.length > 50) history.shift();
      $("tempValue").textContent = Number(d.temperature).toFixed(1) + "°C";
      $("humValue").textContent  = Math.round(d.humidity) + "%";
      $("ldrValue").textContent  = d.ldr;
      $("tempStatus").textContent = d.temperature < 20 ? "Cool" : d.temperature > 28 ? "Warm" : "Comfortable";
      $("humStatus").textContent  = d.humidity < 30 ? "Dry" : d.humidity > 60 ? "Humid" : "Comfortable";
      $("ldrStatus").textContent  = d.ldr > Number($("threshold").value) ? "Dark" : "Bright";

      const tr = document.createElement("tr");
      [new Date(d.timestamp).toLocaleString(), Number(d.temperature).toFixed(1), Math.round(d.humidity), d.ldr,
       d.bulbState ? "ON" : "OFF", d.mode].forEach(v => { const td = document.createElement("td"); td.textContent = v; tr.appendChild(td); });
      const body = $("rows"); body.prepend(tr);
      while (body.children.length > 50) body.lastChild.remove();
    });

    db.ref("appliances/bulbState").on("value", s => {
      bulbOn = !!s.val();
      $("bulbToggle").classList.toggle("on", bulbOn);
      $("bulbToggle").setAttribute("aria-checked", bulbOn);
      $("bulbStatus").textContent = bulbOn ? "ON" : "OFF";
    });
    db.ref("settings/mode").on("value", s => { mode = s.val() || "manual"; renderMode(); });
    db.ref("settings/ldrThreshold").on("value", s => {
      const v = s.val() ?? 2500;
      $("threshold").value = v; $("thresholdValue").textContent = v;
    });
  }

  /* ---------- Controls ---------- */
  function toggleBulb() {
    if (mode === "automatic") { alert("Switch to Manual mode to control the bulb."); return; }
    db.ref("appliances/bulbState").set(!bulbOn);          // uses the state kept by the listener above
  }
  $("bulbToggle").onclick = toggleBulb;
  $("bulbToggle").onkeydown = e => { if (e.key === "Enter" || e.key === " ") { e.preventDefault(); toggleBulb(); } };

  const setMode = m => db.ref("settings/mode").set(m);
  $("modeManual").onclick = () => setMode("manual");
  $("modeAuto").onclick   = () => setMode("automatic");
  function renderMode() {
    $("modeManual").classList.toggle("active", mode === "manual");
    $("modeAuto").classList.toggle("active", mode === "automatic");
    $("thresholdBox").hidden = mode !== "automatic";
  }

  // Input validation: always an integer clamped to 0-4095; write only when the slider is released
  $("threshold").oninput  = e => $("thresholdValue").textContent = e.target.value;
  $("threshold").onchange = e => {
    const v = Math.min(4095, Math.max(0, parseInt(e.target.value, 10) || 0));
    db.ref("settings/ldrThreshold").set(v);
  };

  /* ---------- CSV export ---------- */
  $("btnCsv").onclick = () => {
    let csv = "Timestamp,Temperature,Humidity,Light,Bulb,Mode\n";
    history.forEach(r => {
      csv += `${new Date(r.timestamp).toISOString()},${r.temperature},${r.humidity},${r.ldr},${r.bulbState ? "ON" : "OFF"},${r.mode}\n`;
    });
    const url = URL.createObjectURL(new Blob([csv], { type: "text/csv" }));
    const a = document.createElement("a");
    a.href = url; a.download = "sensor-data.csv"; a.click();
    URL.revokeObjectURL(url);
  };
</script>
</body>
</html>

// OPTIONAL extension - Firebase Cloud Functions (Node.js). Not required for Tasks 4-5.
// Deploy with: firebase deploy --only functions
const functions = require("firebase-functions");
const admin = require("firebase-admin");

admin.initializeApp();
const db = admin.database();

// Runs whenever the ESP32 logs a new reading.
exports.processSensorData = functions.database
  .ref("/sensorData/{pushId}")
  .onCreate(async (snapshot) => {
    const data = snapshot.val();
    if (data.temperature > 40) {
      console.log("Temperature alert:", data.temperature);
      // hook for a notification (email, push, ...)
    }
    return null;
  });

// Audit trail: remember every change of the bulb state.
exports.logBulbCommand = functions.database
  .ref("/appliances/bulbState")
  .onUpdate(async (change) => {
    const before = change.before.val();
    const after = change.after.val();
    if (before === after) return null;
    return db.ref("/auditLog").push({
      command: "bulbState",
      newValue: after,
      timestamp: admin.database.ServerValue.TIMESTAMP,
    });
  });

Problems encountered and their solutions

ProblemCauseSolution
Slow queries while building the schemaDeeply nested pathsFlattened the structure to /sensorData, /appliances, /settings
Toggle did not flip the bulbThe state has to be read before writing the oppositeKeep the latest value from the real-time listener and write !bulbOn
Dashboard and ESP32 fighting over the stateBoth change bulbState (manual vs automatic)Manual toggle is blocked in automatic mode; the ESP32 ignores manual commands in automatic mode
Google sign-in popup failsThe site domain is not authorisedAdd the domain under Authentication → Authorized domains
Table kept growingEvery new reading added a rowCap the table and in-memory history at 50 readings

Brief reflection on the assignment

Reflection. Schema design turned out to be as important as the code. A flat JSON structure and real-time listeners made the dashboard simple, and rules and authentication made it safe enough to connect to a real appliance. I also learned that authentication alone is not enough: the database rules decide what a signed-in user may do.
