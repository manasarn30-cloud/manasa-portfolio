03 — Projects

From a blinking LED to a cloud-connected monitor.

01 · Browser-Controlled LED

ESP32 · HTTP

An ESP32 acting as a web server on the local network. A browser page turns the onboard LED on and off through a small REST API.

What I built

  • Endpoints /api/on, /api/off and /api/status on the ESP32 WebServer library
  • A responsive page that polls status every 500 ms and updates without reloading
  • Button response of roughly 50–100 ms on my local network

Takeaway

HTTP is pull-based, which works for occasional updates but not for real-time control. That led straight to the next project.

02 · Cloud Relay Control over MQTT

ESP32 · Adafruit IO · Relay

Switching a mains bulb from anywhere on the internet. A dashboard publishes to an Adafruit IO feed over MQTT, and the ESP32 subscribes and drives a 5 V relay module.

What I built

  • MQTT publish/subscribe control with a callback that parses ON/OFF commands
  • A relay that isolates 230 V AC from the ESP32. Only the live wire is switched, and the relay defaults to OFF at start-up
  • Dashboard-to-bulb latency under about a second

What went wrong, and the fix

The relay module is active-LOW: a LOW signal turns it on. I caught this by testing the logic at low voltage and reading the datasheet before connecting mains, then wrapped it in RELAY_ON / RELAY_OFF constants.

03 · Google Assistant Voice Control

IFTTT · Webhooks

"Hey Google, activate bulb on" now switches the relay, chaining several services together without a custom app.

Google Assistant → IFTTT → Webhook → Adafruit IO → MQTT → ESP32 → Relay

What I built

  • Two IFTTT applets (on and off) that send a JSON POST to the Adafruit IO feed
  • End-to-end latency of about 2–3 seconds, which I worked down by keeping the WiFi connection persistent and making requests asynchronous
  • A troubleshooting guide covering IFTTT rate limiting, account mismatches and feed-name errors

Takeaway

Latency adds up across every hop, so I broke it down per stage before optimising anything.

04 · Smart Environment Monitor

ESP32 · Firebase · Web dashboard

A system that logs temperature, humidity and light every 2 seconds, stores it in Firebase Realtime Database, and lets me control the relay manually or automatically from a web dashboard.

Hardware and firmware

  • DHT11 for temperature and humidity, and an LDR module on the ESP32's 12-bit ADC (0–4095, not Arduino's 0–1023)
  • The raw LDR readings jumped erratically, so I average 15 samples taken 8 ms apart in software
  • Automatic mode compares the filtered light level against an adjustable threshold. Manual mode follows the dashboard toggle

Cloud and dashboard

  • Flat database layout (/sensorData, /appliances, /settings) with stream listeners on the ESP32 for commands
  • Firebase Authentication (email/password and Google) with security rules limiting access to signed-in users
  • Live sensor cards, bulb toggle, mode selector, threshold slider, a table of the last 50 readings, and CSV export
