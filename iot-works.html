Entry 1: ESP32 Web Server & LED Control

10 Sept 2026

Started with the fundamentals: Wi-Fi, HTTP and GPIO. Turned an ESP32 into a web server that controls its onboard LED from a browser on the same network.

What I did

  • Connected the ESP32 to a 2.4 GHz network and read its IP from the Serial Monitor
  • Wrote routes /api/on, /api/off, /api/status and a control page that calls them with fetch
  • Polled the status every 500 ms so the page always shows the real LED state

Result

Button response about 50–100 ms and page load about 200–300 ms on the local network.

“HTTP only answers when asked. For control from anywhere, I need a push-based approach.”

Entry 2: Cloud Relay Control over MQTT

Sept 2026

Moved from the local network to the cloud: a dashboard toggle publishes to an Adafruit IO feed, and the ESP32 subscribes and switches a relay that controls a 230 V bulb.

What I did

  • Set up an Adafruit IO feed and dashboard toggle
  • Wired the relay so only the live wire is switched, and made the relay start in the OFF state
  • Found the relay is active-LOW by testing at low voltage before touching mains (about 30 minutes)

Result

Dashboard-to-bulb latency under about one second.

“Reading the datasheet and testing in stages is what separates a working system from a safety incident.”

Entry 3: Google Assistant Voice Control

Sept 2026

Chained Google Assistant, IFTTT, Adafruit IO and the ESP32 so that “activate bulb on” switches the bulb.

What I did

  • Created two IFTTT applets (ON and OFF) that POST to the Adafruit IO feed
  • Handled IFTTT rate limits and exact-phrase matching during testing
  • Broke down the delay per service (about 2.85 s in total), then made the connection persistent and requests asynchronous (about 1.5 hours)

Result

End-to-end time came down from about 2.85 s to roughly 1.2–1.5 s.

“Latency adds up across every hop. I had to measure each one before I could improve any of them.”

Entry 4: Firebase Dashboard & Authentication

Sept 2026

Built a secure real-time web dashboard on the Firebase Realtime Database, with email/Google login and security rules.

What I did

  • Designed a flat database structure after slow queries on a nested one (about 30 minutes)
  • Added Firebase Authentication and rules so only signed-in users can read data or control the bulb
  • Built live sensor cards, a bulb toggle, mode selector, threshold slider and a history table

Result

Dashboard and ESP32 stay in sync in about 1–2 seconds.

“Schema design matters as much as code, and authentication alone is not enough: the rules decide what a signed-in user may do.”

Entry 5: Logging, Automation & CSV Export

Sept 2026

Combined everything into one system: DHT11 and LDR monitoring, timestamped logging, manual/automatic control and data export.

What I did

  • Fixed erratic LDR readings (0 to 4095 jumps) with 15-sample software averaging (about 45 minutes)
  • Corrected thresholds after finding the ESP32 ADC is 12-bit (0–4095), not 10-bit (about 30 minutes)
  • Logged a record every 2 seconds to Firebase and added CSV download on the dashboard

Result

DHT11 about ±0.5 °C after averaging; LDR about ±50 counts; relay response about 10 ms.

“A demo that works once is different from a system that keeps working unattended. I designed for noise, safe defaults and failures.”
