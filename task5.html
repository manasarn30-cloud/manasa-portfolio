Objective of the complete IoT system

Combine the earlier tasks into one working system. An ESP32 monitors temperature, humidity and light 24/7, logs every reading to Firebase with a timestamp, switches a bulb manually from a dashboard or automatically based on room brightness, and lets the data be reviewed and exported as CSV.

DHT11 temperature and humidity monitoring

The DHT11 is a digital single-wire sensor on GPIO4 (with a pull-up resistor on the data line). Range: 0–50 °C (±2 °C) and 20–90 % RH (±5 %). It can be read at most once every 2 seconds, so the firmware reads it on a 2-second timer, and if a read fails (NaN) that cycle is skipped instead of logging a bad value.

Common mistakes: reading faster than every 2 s, forgetting the pull-up resistor on the DATA line, and not handling a failed read (timeout).

LDR-based light level monitoring

The LDR module (voltage divider with an analog output) is connected to GPIO34, an input-only ADC1 pin. The ESP32 ADC is 12-bit (0–4095), not 10-bit like an Arduino Uno. A higher reading means a darker room. The value is a relative brightness, not lux.

Manual bulb control

In manual mode the dashboard toggle writes true/false to /appliances/bulbState. The ESP32 holds a stream on that path, receives the change within about a second and drives the relay (GPIO26, active-LOW).

Automatic bulb control using LDR, and how the logic works

In automatic mode the ESP32 decides on its own, every 2 seconds:

ldr = average of 15 readings
shouldBeOn = (ldr > ldrThreshold)        // darker than threshold → light needed
if shouldBeOn != relayState:
      apply relay, then write the new state to /appliances/bulbState

Because the ESP32 makes the decision locally, automation keeps working even if the dashboard is closed. The new bulb state is written back to Firebase so the dashboard stays correct.

The ESP32 ignores manual commands while in automatic mode, so the two cannot fight each other.

LDR threshold and calibration method

  1. Open the Serial Monitor (or the dashboard) and note the light value in a bright room and in a dark room.
  2. Choose a threshold between the two. The default is 2500 on the 0–4095 scale.
  3. Set it with the dashboard slider. It is saved in /settings/ldrThreshold and the ESP32 receives it without a restart.
  4. Test by covering and uncovering the sensor, and adjust until the switching point feels right.
Noise handling. Raw LDR readings jumped erratically (for example 500 → 2000 → 300 in consecutive reads). Instead of adding a hardware capacitor, I average 15 samples taken 8 ms apart in software. It is cheap, adds only about 120 ms and can be tuned in code. The slider range is validated to an integer between 0 and 4095.

Historical data logging in Firebase

Every 2 seconds the ESP32 pushes one JSON record to /sensorData. Firebase assigns each record a unique, time-ordered key, so limitToLast(50) returns the latest 50 readings. At this rate the system logs up to 43,200 records per day.

Show ESP32 firmware (task5_smart_monitor.ino)
// Tasks 4 & 5 - ESP32 environmental monitor (DHT11 + LDR) with Firebase RTDB logging,
// manual/automatic relay control and fail-safe behaviour.
// Libraries: "Firebase ESP Client" (Mobizt), "DHT sensor library" (Adafruit)
#include <WiFi.h>
#include <DHT.h>
#include <Firebase_ESP_Client.h>
#include <addons/TokenHelper.h>

#define WIFI_SSID      "YOUR_WIFI_SSID"
#define WIFI_PASSWORD  "YOUR_WIFI_PASSWORD"
#define API_KEY        "YOUR_FIREBASE_WEB_API_KEY"
#define DATABASE_URL   "https://manasa-easports-default-rtdb.asia-southeast1.firebasedatabase.app"
#define DEVICE_EMAIL   "device@example.com"     // a dedicated Firebase Auth user for the ESP32
#define DEVICE_PASS    "YOUR_DEVICE_PASSWORD"

#define DHT_PIN   4
#define LDR_PIN   34            // input-only ADC1 pin
#define RELAY_PIN 26
#define RELAY_ON  LOW           // active-LOW relay module
#define RELAY_OFF HIGH
#define SENSOR_INTERVAL 2000UL
#define OFFLINE_TIMEOUT 30000UL // relay forced OFF if Wi-Fi is down this long

DHT dht(DHT_PIN, DHT11);
FirebaseData fbWrite, fbSettings, fbBulb;   // one object per stream / one for writes
FirebaseAuth auth;
FirebaseConfig config;

int ldrThreshold = 2500;        // 0-4095 (12-bit ADC); higher value = darker room
bool relayState = false;
String mode = "manual";
unsigned long lastPush = 0, lastOnline = 0;

// 15-sample average (8 ms apart) to smooth LDR noise
int readLDR() {
  long sum = 0;
  for (int i = 0; i < 15; i++) { sum += analogRead(LDR_PIN); delay(8); }
  return sum / 15;
}

void applyRelay(bool on) {
  relayState = on;
  digitalWrite(RELAY_PIN, on ? RELAY_ON : RELAY_OFF);
  Serial.println(on ? "Relay: ON" : "Relay: OFF");
}

void handleStreams() {
  // /appliances/bulbState  (manual command from the dashboard)
  if (Firebase.RTDB.readStream(&fbBulb) && fbBulb.streamAvailable() && fbBulb.dataType() == "boolean") {
    bool wanted = fbBulb.boolData();
    if (mode == "manual" && wanted != relayState) applyRelay(wanted);
  }
  // /settings  (mode + ldrThreshold)
  if (Firebase.RTDB.readStream(&fbSettings) && fbSettings.streamAvailable()) {
    String p = fbSettings.dataPath();
    if (fbSettings.dataType() == "json") {                 // first event delivers the whole node
      FirebaseJson &j = fbSettings.jsonObject();
      FirebaseJsonData d;
      if (j.get(d, "mode")) mode = d.stringValue;
      if (j.get(d, "ldrThreshold")) ldrThreshold = d.intValue;
    } else if (p == "/mode") {
      mode = fbSettings.stringData();
    } else if (p == "/ldrThreshold") {
      ldrThreshold = fbSettings.intData();
    }
    Serial.printf("Settings -> mode=%s threshold=%d\n", mode.c_str(), ldrThreshold);
  }
}

void setup() {
  Serial.begin(115200);
  pinMode(RELAY_PIN, OUTPUT);
  digitalWrite(RELAY_PIN, RELAY_OFF);           // always boot with the relay OFF
  dht.begin();

  WiFi.begin(WIFI_SSID, WIFI_PASSWORD);
  while (WiFi.status() != WL_CONNECTED) { delay(500); Serial.print("."); }
  Serial.println("\nWiFi connected");

  config.api_key = API_KEY;
  config.database_url = DATABASE_URL;
  auth.user.email = DEVICE_EMAIL;
  auth.user.password = DEVICE_PASS;
  config.token_status_callback = tokenStatusCallback;
  Firebase.begin(&config, &auth);
  Firebase.reconnectWiFi(true);

  Firebase.RTDB.beginStream(&fbBulb, "/appliances/bulbState");
  Firebase.RTDB.beginStream(&fbSettings, "/settings");
  lastOnline = millis();
  Serial.println("System initialised");
}

void loop() {
  // Fail-safe: no Wi-Fi for too long -> relay OFF
  if (WiFi.status() == WL_CONNECTED) lastOnline = millis();
  else if (relayState && millis() - lastOnline > OFFLINE_TIMEOUT) applyRelay(false);

  if (Firebase.ready()) handleStreams();

  if (millis() - lastPush >= SENSOR_INTERVAL) {
    lastPush = millis();

    float t = dht.readTemperature();
    float h = dht.readHumidity();
    int ldr = readLDR();
    if (isnan(t) || isnan(h)) { Serial.println("DHT read failed - skipping"); return; }

    // Automatic mode: dark room (high LDR value) -> bulb ON
    if (mode == "automatic") {
      bool shouldBeOn = (ldr > ldrThreshold);
      if (shouldBeOn != relayState) {
        applyRelay(shouldBeOn);
        Firebase.RTDB.setBool(&fbWrite, "/appliances/bulbState", relayState);
      }
    }

    // Log one timestamped record per reading under /sensorData/<pushId>
    FirebaseJson json;
    json.set("temperature", t);
    json.set("humidity", h);
    json.set("ldr", ldr);
    json.set("bulbState", relayState);
    json.set("mode", mode);
    json.set("timestamp/.sv", "timestamp");     // server-side timestamp (ms)
    if (Firebase.ready()) Firebase.RTDB.pushJSON(&fbWrite, "/sensorData", &json);

    Serial.printf("Temp: %.1fC | Humidity: %.0f%% | LDR: %d\n", t, h, ldr);
  }
}

Safety. 230 V mains can kill. The relay separates the ESP32 (3.3 V logic) from the mains side. Only the live wire goes through the relay; neutral goes straight to the bulb. All logic was first tested with the relay unconnected to mains, and the relay starts in the OFF state.

Where this could be used

The same logger answers practical questions once the data is exported as CSV:

  • When is a room coldest, so heating or cooling can be scheduled better?
  • At what time does natural light peak, so artificial lighting can be reduced?
  • How does humidity change over the day, and does it need ventilation?

It runs on the free Firebase tier and cheap parts (ESP32, DHT11, LDR), and the data can be analysed in Excel, Python or R.

Reflection

Reflection. A working demo and a reliable system are different things. Sensor noise, hardware quirks (ADC resolution, relay polarity) and network failures only show up when the system runs unattended, so I designed for them: filtering in software, safe defaults and a fail-safe. I also learned to test staged: logic at low voltage first, mains last.
